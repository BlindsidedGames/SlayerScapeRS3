# SlayerScape RS3 - Agent Guide

## Purpose
This Vite + React app (with PWA via `vite-plugin-pwa`) builds a static bundle that is hosted under the main site repo `My Site/BlindsidedGames` at the path `/games/slayerscape/` (served via GitHub Pages/CNAME as `https://blindsidedgames.com/games/slayerscape/`).

## Project structure (source repo: `SlayerScapeRS3`)
- `src/` - React app source, data, styles. Static assets live under `public/icons` (and `public/icons for Import`).
- `vite.config.ts` - sets `base = "/games/slayerscape/"`, PWA config (start_url/scope/manifest icons relative to base).
- `public/manifest.webmanifest` - PWA manifest source.
- `dist/` - build output (generated).

## Deployment target (site repo: `My Site/BlindsidedGames`)
- Built files are copied to `games/slayerscape/` in the site repo. That folder is what Pages serves.

## How to build & publish to the site
1) From `SlayerScapeRS3`:
   - `npm install` (once)
   - `npm run build`
   - Ensure SPA fallback: copy `dist/index.html` to `dist/404.html` (already scripted here when we deploy).
2) Copy build to site repo:
   - Replace contents of `C:\Users\mattr\Documents\Repositories\My Site\BlindsidedGames\games\slayerscape` with `dist/*`.
3) Push the site repo to GitHub Pages (CNAME already points to `blindsidedgames.com`). The site will serve the new build at `/games/slayerscape/`.

## Notes
- Asset paths: code uses `import.meta.env.BASE_URL` via a helper `assetPath(...)` so icons resolve correctly under the `/games/slayerscape/` base. Keep `vite.config.ts` base in sync if the path changes.
- Service worker: generated by `vite-plugin-pwa` (`generateSW`). If assets seem cached, hard refresh or unregister SW in devtools.
- Data/API: pulls data from RuneScape endpoints (wiki cargoquery, hiscores, runemetrics) with CORS proxy fallbacks defined in `App.tsx`.
- Changelog: update `src/changelog.ts` after every change (newest first). Do **not** bump `package.json`/APP version unless explicitly requested; append new notes to the top of the current version entry instead of creating a new version.
